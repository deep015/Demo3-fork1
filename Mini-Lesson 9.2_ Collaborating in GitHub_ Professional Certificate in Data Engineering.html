Overview

GitHub is a software collaboration tool that allows teams to build software together. Team members may be located all over the world, and GitHub allows them to work together on a project without interfering with each other’s work.

Prior to reviewing this mini-lesson, be sure you have set up your own account in GitHub and set up the Git Client on your local machine. If you need help with these steps, review Video 9.5.

In this mini-lesson, you will first learn how to make changes in GitHub. Then, you will learn how to make a copy of a public repository by forking. Finally, you will learn how to create a pull request to let the owner of the repository know that you are recommending changes.

Making Changes in GitHub

First, in GitHub, create a new repository called “GitHubMiniLesson”:

Accept all of the other default settings.

After your new repository is created, select the clipboard icon for the section labeled as “…or create a new repository on the command line”. This will copy the script to the clipboard. Save this script to use again later:

If you are using a Windows computer, open up Git Bash. To do this, search for “Git Bash” and select the Git Bash application icon:

If you are using a Mac, open a Terminal window to complete the following steps.

Make a directory called “GitHubMiniLesson” and change (cd) to the new directory:

Paste the scripts you saved on the clipboard into Git Bash and select “Return”:

This will initialize the repository for you using command-line commands. Some comments regarding each line of the script:

  1. echo "# GitHubMiniLesson" >> README.md

    >This will create a file called README.md. The extension .md means that it is a Markdown file. Note that echo is an operating system command that outputs the string it is being passed as an argument. The >> means redirect to the standard output. In this case, you will be redirecting the output to a file you will be creating called README.md.

  2. git init

    The git init command creates a new repository in your local machine.

  3. git add README.md

    The git add command adds the newly created file README.md to the local repository.

  4. git commit -m "first commit"

    The git commit command saves all changes to the local repository.

  5. git branch -M main

    You will be associating your work with the main branch since you are initializing the repository.

  6. git remote add origin git@github.com:<your user name>/GitHubMiniLesson.git
    Now you are ready to move the changes from your local repository to the cloud. The git remote command will initiate that process.
  7. git push -u origin main

    The git push command pushes your local changes from the main branch local repository to the cloud.

The file README.md is now part of your GitHubMiniLesson repository in the cloud.

Now the repository is available in the cloud, and people can collaborate on the project.

From GitHub, in the new GitHubMiniLesson repository, select the README.md file and then select “Edit” to edit the file:

Add “We are experimenting with GitHub” to the README.md file:

Now scroll down, enter “Made changes to README.md” in the “Commit changes” field, and select the “Commit changes” button.

Now you have changed your repository in the cloud. However, your local repository and your remote repository are not in sync. You can open the file README.md using VS Code to verify that the file is not up to date:

Run the following command from Git Bash to refresh your local repository with the latest version that exists in the cloud:

git pull --verbose

The attribute verbose tells Git to display everything that it is doing.

Git pulls the files that were modified on the server (README.md) and that are different from the version on the local machine. Now your local copy of README.md has been refreshed with the changed version that was on the server:

Forking

Assume that there is a public repository and you have an awesome idea for enhancing a feature that you want to share with the owner of the repository. Forking allows you to make a copy of a public repository to your GitHub account. You can then make a copy of the repository locally, modify it, and publish it to your copy of the repository in the cloud. Later in this mini-lesson, you will learn how to let the owner of the repository know about your changes by creating a pull request. It will be up to the owner of the repository to accept and merge your changes or not.

In your browser, navigate to the Spoon-Knife GitHub repository Links to an external site.. Select “Fork” to create a copy of the Spoon-Knife repository to your account:

A copy of the Spoon-Knife repository is created for you in GitHub:

In your GitHub repository, select “Code” and then select the clipboard to copy the contents of the script to the clipboard:

Now, in your Git Bash Terminal, type “git clone” and paste the contents of the clipboard to the Git Bash shell and select Enter:

git clone git@github.com:<your username>/Spoon-Knife.git

Now you have a copy of the repository on your local machine.

Open your local copy of the README.md file in VS Code and add the following sentence at the end of the file: “Testing pushing changes and then forking”.

Save your changes.

Open Git Bash and navigate to the Spoon-Knife folder. First, add the changes using the following command: git add. Then, enter another command:

git commit -m "my suggestions for Spoon-Knife repository”

Now you are ready to push changes to the GitHub repository. In Git Bash enter the following command:

git push -u origin main

Now you have pushed your changes from your local machine to the server. If you go to GitHub and look at README.md, you should be able to see your changes there:

You have now successfully pushed changes from your local machine to the server.

Now you are ready to start collaborating with other teams using GitHub and to make your portfolio available to the industry.

Here are some of the most common Git commands:

Common Git Commands

Command

Description

git init

The git init command is used to initialize your local directory for the first time when creating new repositories.

git add <file name>

The git add command is used to add new files to the repository.

git commit -m "<comments>"

The git commit command saves all changes to the local repository.

git branch -M main

 

The git branch command associates your work with the main branch when initializing the repository.

git remote add origin git@github.com:<your user name>/<repository name>.git

You can move changes from your local repository to the cloud. The git remote command will initiate that process.

git push -u origin main

The git push command pushes your local changes from the main branch local repository to the cloud.

git clone git@github.com:<your user name>/<repository name>.git

You can use the git clone command to copy the repository from GitHub to your local computer.

Fork

Fork is a GitHub command meant to make a copy of a public repository to your GitHub user in the cloud. You can then copy the repository to your local machine using git clone.

Pull request

A pull request is sent to the owner of a public repository after you have made changes. They may or may not accept your changes and merge your changes with their code.
